# 每轮优化后的改进提交

当前策略：2026-11-03 改为每天一次 UTC 23:40（北京时间 07:40）开始、20 分钟的自动窗口，
每 UTC 日最多一次尝试、一次成功提交；对账移到北京时间 09:00。

此前补充：2026-10-30 改为北京时间 08:00、20:00 两个自动窗口，
每窗口最多一次尝试；2026-11-03 改为每 UTC 日最多三次成功提交。
成功以有效 Kaggle 提交 ID 为准，同一 ID 只计一次；失败上传不占每日成功额度，
但保留尝试记录、同组合去重和未知结果先对账。以下保留此前策略的演变记录。

2026-10-29，用户授权把原“每天一次、北京时间20:00窗口”改为：每轮优化结束，
如产生相对已提交组合的新改进且通过完整官方验证，就由统一队列请求提交。
本次改动不购买额度，不增加模型任务次数、CPU、内存或GPU上限。

当前规则通过 Kaggle `get_competition` 与 `list_competition_pages(rules)` 核实：
[官方比赛规则](https://www.kaggle.com/competitions/google-verifiable-quantum-circuit-compilation/rules)
限制每天最多五次提交，最多两份最终选择；比赛截止仍为北京时间2027-01-21 07:59。
提交额度采用 UTC 日（北京时间08:00重置），模型预算仍采用北京时间日期。
真实上传前需查询完整的当日团队提交记录，把手动上传也计入平台配额。

## 执行方式

- `submission_policy: after_optimization` 启用新模式；未配置的历史部署继续使用
  `daily_window`，保留旧测试和历史配置的可解释性。
- 优化正常结束后，控制层先检查当前best、已提交组合、未知上传与配额。
  没有新改进不启动提交模型；有改进持久加入submit队列，复用现有执行锁。
- 自动提交在空闲时优先；不抢占正在运行的优化或验证。相近完成事件合并为待执行
  的一次提交，真正取得执行权时重新准备最新best，避免重复或提交较旧版本。
- 2026-10-30 补充跨日补交：当天额度用完后保留未提交的最佳改进，北京时间次日
  08:00 额度恢复后，在当前任务结束时优先提交，无需再完成一次优化。已有排队请求
  继续使用；若前次任务因平台额度耗尽等原因结束但未上传，则每个新额度日自动检查
  一次。检查和去重状态持久化，重启不会重复创建请求；等待期间的新改进纳入执行时
  的最佳组合。仍受暂停、模型预算、截止时间、完整验证和未知上传对账约束。
- 首次切换可识别最新的旧runner已完成优化，使用稳定触发ID去重；不把历史每次
  运行重放为上传。暂停自动调度期间不自动提交，手动操作仍受全部门槛约束。
- 上传前继续执行 `pipeline.prepare → reserve → upload/submit → record`。
  完整验证、产物及来源绑定、最佳组合变化检查继续有效。
- 本地预留占用一次尝试；失败、取消、拒绝均保留该次记录。同一已尝试组合不自动
  重传。缺ID的不确定上传先对账；已有ID但评分未知时，下一份合格改进可用剩余额度。
- 提交或对账仍消耗模型任务次数。预算由控制台激活配置决定；用户已于2026-10-30
  先从每天6次提高至20次，后提高至30次，跨日补交本身不增加预算。
  若额度不足，任务显示等待预算，不能把平台剩余次数当成可用模型次数。
- 2026-10-30 补充失败后对账：每个缺少提交 ID 的失败或未确认上传尝试自动安排
  一次只读对账，包括明确拒绝但未取得 ID 的上传。每个 token 对应独立任务，
  已开始的旧查询不能代替本次失败后的查询；重复调度及重启不会重复创建。
  对账遵守模型预算、暂停和截止时间；结果仍未确认时不递归创建任务或重传。
- 每日20:55对账保留为兜底，新模式手动查询不限制到固定窗口。旧19:25提交保护
  区间不再阻挡普通作业；优化时段本身保持原配置。

## 数据与验证

新上传预留记录加入 `quota_date`、`quota_timezone`、`submission_policy`，保留原
`date` 作为原始台账日期。历史有时间戳的记录按预留时间或平台回执时间换算额度日。
UI的今日已用和剩余额度来自同一共享策略函数；不再用“存在一次提交”判定用尽。

测试覆盖同日多次改进、第五次与第六次、北京时间午夜与UTC午夜、未知上传、
已知ID无评分、组合去重、优化结束触发与合并、暂停、过期作业，以及旧策略兼容。
跨日补交另覆盖午夜不提前恢复、08:00 恢复后优先执行、前次任务已结束但未上传、
重启去重、同日不循环重试及已提交最佳组合不重复上传。
科学验证证据继续复用，没有为提交策略开发重跑科学测试或直接上传测试文件。
