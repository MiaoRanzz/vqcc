# VQCC 私有监控与控制台开发文档

版本：0.1 · 日期：2026-10-29（Asia/Shanghai）

状态：产品范围已确认，供开发实施。本文描述待开发的 Web 控制台，不表示页面或下述 HTTP API 已部署。

现状依据：源码提交 `5e0f54a` 及本日只读检查；后续实现前应核对接口变化。

## 1. 目标与已确认的决定

控制台要帮助使用者随时回答五个问题：

1. 系统是否正常，当前在研究、生成、验证还是等待？下一步是什么？
2. 哪个任务、哪组参数产生了改进？结论的验证依据在哪里？
3. 当前用哪个模型、消耗了哪些资源，还允许启动多少模型任务？
4. 如何启动一次实验、调整后续配置、停止指定任务，而不破坏已有结果？
5. 今天会提交什么、为什么可以或不可以提交、Kaggle 是否已给出成绩？

用户已确认的范围：

| 决定 | 首版要求 |
|---|---|
| 使用者与访问 | 个人使用；服务器私有部署，经 SSH 转发访问 |
| 操作能力 | 监控、配置、创建实验、启动验证、暂停后续调度、停止当前任务 |
| 实验入口 | 本地生成器实验与 Codex 研究两种入口；明确区分额度消耗 |
| 并发策略 | 手动任务默认排队；停止当前任务是单独操作 |
| 模型预算 | 每日顶层模型任务次数、单次时长限制；token 仅用于观测 |
| 既有比赛规则 | 继续遵守完整验证、改进晋级、北京时间每日最多一次提交及既定窗口 |
| 本次交付 | 开发文档；不在本次启动 Web 服务或修改优化任务 |

以下为工程默认，可在实现评审中调整，但不能扩大上述授权：中文界面、桌面优先、窄屏可查看；单实例后端；同一时刻一个受监督的计算任务；复用既有数据与比赛业务逻辑。

首版不包含在线 IDE、任意 shell 终端、多用户协作、公网服务、自动公开代码/数据、自动增加付费额度、账户余额爬取和精确费用预测。已有授权内的日常提交不增加每次人工审批。

### 2.2 必须新增，不能由前端猜测的能力

| 缺口 | 当前事实 | 开发要求 |
|---|---|---|
| 持久队列 | 手动 runner 遇到共享锁返回 busy | 新增持久队列、取消排队、等待原因、重启恢复 |
| 本地作业统一监督 | 直接调用 pipeline 不经过 runner 的 CPU/RSS/时间监控 | 本地生成/验证也必须经统一 supervisor 执行 |
| 精确停止 | 缺少仅按 run ID 停止当前任务的公共接口 | 新增取消请求和监督器处理；保持后续调度不变 |
| 每日模型次数 | 当前未实现 | 新增按北京时间日期的原子预留与计数 |
| 实际模型快照 | runner 继承全局设置，历史记录未固化模型 | 新作业明确传入模型并记录解析后配置 |
| 阶段进度 | 日志无完整阶段事件和统一时间戳 | 增加结构化事件；没有分母时不显示百分比 |
| 实时资源 | 只有结束后的峰值 RSS 等信息 | 增加轻量采样，并明确进程归属和采样时间 |
| 状态读取 | pipeline status 会获取被完整验证长时间持有的锁 | 新增非阻塞只读快照，不能用 CLI 高频轮询 |
| HTTP 重试 | CLI 没有通用 HTTP 幂等键 | 新增操作 ID、请求体指纹和持久结果 |
| 配置生效 | tick 和 daemon 的读取周期不同 | 新增配置版本、待生效状态、任务启动快照 |
| 跨文件一致性 | JSON 单文件原子替换，不是多文件事务 | 返回一致性/新鲜度标记，必要时保留上次有效快照 |

已有日志、研究文本和元数据可能正在写入。页面读不到结束报告时，不能直接判断任务仍在运行；旧 daemon heartbeat 也不能直接证明进程死亡。

## 3. 页面结构与核心交互

导航限定为七个主页面。跨页使用稳定的 job、run、experiment、submission ID，保留筛选条件和可分享的本地页面链接。

| 页面 | 主要内容 | 主要操作 |
|---|---|---|
| 总览 | 当前一句话状态、三题最佳、预算、资源、今日提交、告警 | 查看当前任务、打开实验、新建任务 |
| 任务与队列 | 当前执行、手动/自动队列、历史运行、阶段时间线 | 取消排队、停止指定任务、暂停/恢复自动调度 |
| 实验 | 筛选、详情、同题比较、父子谱系、失败结果 | 复制为新实验、验证、晋级有效候选 |
| 启动工作台 | 本地实验、Codex 优化两种表单 | 预检、复制已有实验参数、加入队列 |
| 研究 | 假设、论文/讨论来源、复现状态、负结果 | 排序/停用假设、关联实验、转为研究任务 |
| 提交 | 当前组合、资格门槛、每日台账、平台状态 | 预览组合、在窗口内请求提交、只读对账 |
| 配置与额度 | 项目模型、次数/时长、资源、时间表、配置历史 | 保存新版本、回滚为新版本、查看生效差异 |

### 3.1 总览

首屏不展示大量 JSON、哈希和内部路径；这些放在“依据/详情”中。

~~~
┌ VQCC  控制台        北京时间 UTC+8       数据更新于…… ┐
│ 当前：InvSqrt 完整验证中 · 已运行 01:12 · 最长 20:00 │
│ [查看任务] [暂停后续自动任务] [停止当前任务]         │
├ DQI 最佳成本 ─ InvSqrt 最佳成本 ─ DFTHC 最佳成本 ───┤
│ 各题变化、验证状态、父版本；点击查看证据             │
├ 本地组合改善 ─ 平台成绩：未知 ─ 今日名额：已使用 ───┤
├ CPU / RAM / GPU / 磁盘 ─ 今日模型任务次数 / 时长 ───┤
│ 待处理：某候选未验证；某次上传结果待对账             │
│ 下一步：排队实验……；下一提交窗口……                 │
└ [理解优化流程] [新建本地实验] [启动 Codex 优化] ────┘
~~~

要求：

- 当前一句话来自结构化阶段；只有日志文本时写“最近事件：……”，不能提升为确定阶段。
- 三题卡片显示“官方验证成本，越低越好”；组合卡片注明比较基准 ID。
- 平台分数与本地改善分栏。缺平台数据用“未知/尚未返回”，不能用 0。
- 配置额度、已知 token、服务器资源分别展示。普通页面刷新不调用模型。
- CPU 用“已使用核数 / 允许核数”；内存标“RSS 监测、170 GiB 提前停止”，不称为硬限额。
- GPU 未分配、闲置与监控不可用分别显示；不可用不能填 0%。
- 告警包含来源、观测时间、阻塞原因和下一步入口，不能只有红色感叹号。

### 3.2 任务与队列

列表显示来源、类型、任务题目、队列位置、状态、等待原因、提交时间、启动时间、已用时长、最长运行时间和配置版本。

详情包含：

1. 结构化阶段时间线及最后事件；无可靠剩余量时不显示 ETA。
2. 当前模型/强度/服务档位或“不调用模型”。
3. 本轮关联候选、研究假设、源码提交。
4. CPU/RSS/GPU/磁盘趋势；采样间断时保留缺口。
5. 已观测 token 与统计覆盖说明。
6. 中文结束报告、停止原因、相关实验链接。

按钮语义必须独立：

| 按钮 | 语义 |
|---|---|
| 取消排队 | 仅取消仍处于 queued/blocked 的作业；若已进入 starting，返回状态冲突，不自动变成停止 |
| 暂停后续自动任务 | 当前继续；停止启动新的自动优化/提交/对账；显式手动作业仍可排队并按统一门槛执行 |
| 恢复自动调度 | 恢复未来符合窗口的任务；不自动补跑过期窗口 |
| 停止当前任务 | 仅针对指定 run ID 请求终止；不自动暂停后续任务 |
| 停止调度器 | 运维操作；仅在没有活跃或状态待核实的作业时允许；否则返回409，先单独处理当前任务；停止后保留 Web 只读能力 |

“暂停后续自动任务”旁明确提示：暂停期间不会自动提交。停止当前任务需要一次简短确认，展示具体任务、未完成验证不算 PASS、已完成记录保留，以及后续调度是否仍启用。

现有 `install_schedule.py --remove` 会连带终止当前 tick，不能直接作为网页的无条件停止接口。新控制层须在同一控制锁下禁止新 dispatch、检查活跃作业，再停止空闲调度器，消除检查与停止之间的竞态。

### 3.3 实验与比较

筛选项：题目、生成器版本、参数、父候选、创建日期、官方验证状态、诊断状态、是否最佳、研究来源、失败原因。

详情分层：

- 摘要：假设、父版本、参数差异、成本变化、是否晋级及原因。
- 证据：生成/初筛、完整官方验证、额外诊断分别列出。
- 资源：Q、Toffoli、T 或任务特有指标；附计量范围。
- 复现：源码版本/快照、环境、验证器指纹、产物清单、可复制命令。
- 失败：失败阶段、反例或错误、影响范围、是否值得换参数再试。
- 谱系：沿 parent 追溯；缺失父节点标为未知，不创造连线。

同题一次比较 2–4 个候选，突出参数差异、成本变化、误差余量及验证环境是否一致。不同题的原始成本不可放在同一高低排名图；跨题只比较相对改进或组合贡献。筛选成本下界与正式验证成本分列。

“复制为新实验”创建新 ID 和不可变参数快照；不覆盖原候选。“晋级”仅请求 pipeline 执行门槛判断，不能手工将任意实验设为最佳。

### 3.4 启动工作台

两个入口始终显示资源类型：

- **本地实验：使用本机算力，不调用 Codex。**
- **Codex 优化：会消耗现有 Codex 使用额度，同时可能运行本地计算。**

本地表单：题目、生成器及版本、父候选、参数、来源数据集、假设说明、运行时长、阶段选择。“仅生成”和“生成并完整验证”明确区分；晋级单独执行。首版支持单组参数；可读取已有批量搜索结果，通用批量网格搜索属于后续扩展。

Codex 表单：目标题目或自动分配、研究目标、可选假设、模型、推理强度、服务档位、时长、允许的资源。高级设置展示是否允许子代理及其共用预算；不能把子代理理解为免费或独立额外额度。

加入队列前显示确认摘要：类型、父候选、参数差异、配置版本、是否调用模型、次数预算占用规则、时长、等待原因。普通实验一次确认即可；不连续弹出重复审批。

### 3.5 研究与流程说明

研究看板按“待复现、实验中、支持、否定、证据不足、来源待核实”分类，关联论文/论坛版本和实验。预期收益标为“未测量先验”，与实际结果分列。读取过主题列表和读取过全文分别计数。

现有研究假设没有统一稳定 ID。控制层首次导入时建立持久 ID 与历史来源的映射；排序和备注变化不改变 ID，不批量重写原研究文件。

总览内嵌以下流程图，并可点击每一步查看当前实例和简明解释：

~~~mermaid
flowchart LR
  A[研究假设或人工参数] --> B[创建隔离候选]
  B --> C[便宜的筛查与生成]
  C --> D[官方完整验证]
  D --> E{是否有可靠改进}
  E -->|有| F[晋级本地最佳]
  E -->|无或证据不足| G[保留结果与失败原因]
  F --> H[组合三题最佳]
  H --> I[窗口与额度检查]
  I --> J[预留并上传提交]
  J --> K[平台接收与评分查询]
~~~

允许导出脱敏实验摘要、对比 CSV 和复现清单。首版不提供直接发布 notebook/数据集或发送论坛消息的按钮。

### 3.6 提交中心

显示三题当前最佳、相对上次提交变化、预览生成时间及预览是否过期。资格清单至少包含：

- 三个组件均具备仍有效的完整验证证据。
- 相对已提交组合存在改进。
- 当前处于北京时间 20:00–20:45 窗口且未过比赛截止。
- 当天名额未使用，无缺提交 ID 的不确定上传。
- ZIP、来源和提交对象匹配；平台近期提交记录已核对。

页面预览不锁定未来实际提交。提交任务获得执行权后重新选取最佳并打包，不能直接上传数小时前的预览包。如果从 prepare 到 reserve 期间 best 已变化，先重新准备，避免把“当日最佳”降格为“某个较早的改进”。

文案：

| 台账状态 | 展示 |
|---|---|
| prepared | 已准备，尚未上传，未占用当天名额 |
| upload_started | 已预留一次尝试；外部进度/结果待确认 |
| 有 ID，无评分 | 已取得提交 ID，平台评分未知；该提交所属北京时间日期的名额已用 |
| 无 ID，结果不确定 | 提交结果待对账；禁止再次上传 |
| scored | 平台已返回评分，附评分来源和查询时间 |
| rejected | 平台明确拒绝，保留原因；不自动重试 |

reserve 后失败、超时或取消均不退还本系统当天尝试名额。停止本地进程不能撤销已经发生的远端提交。对账是查询和登记，不能隐含重传。最终提交选择及公开材料继续单独审阅。

“今日名额”独立按台账日期计算。昨日已有提交 ID 但评分未知，不占今日名额，也不单独阻止今日合格改进；缺 ID 的不确定上传则继续阻止新上传，直到对账完成。

### 3.7 配置与额度

展示三类参数：算法参数、模型参数、调度与机器预算。每个字段提供作用、默认值、允许范围、何时生效及是否影响验证有效性。

当前运行采用的快照与后续默认配置并排展示。历史未记录模型时显示“未记录”；不能补填当前全局设置。回滚生成一个新版本，保留历史。

额度卡片分别显示：

- 今日顶层模型任务：已预留/已启动/可用次数及为提交、对账保留的次数。
- 已观测 token：输入、缓存输入、输出、推理等原始返回字段，附不完整标记。
- 官方账户额度入口：[Codex 用量面板](https://chatgpt.com/codex/settings/usage)；不在本系统填写估算余额百分比。
- 单次时长、今日累计模型任务运行时长、本地计算时长；不把时长换算成确定费用。

## 4. 参数与校验契约

参数 schema 由后端按生成器版本提供，前端不维护独立的一套硬编码范围。创建作业时记录 schema 版本和生成器源码指纹；未知字段拒绝，不静默忽略。

| 题目 | 参数 | 当前默认 | 范围/约束 |
|---|---|---|---|
| DQI | stack_cap | 1 | 整数 1–35 |
| InvSqrt | delta_bits | 14 | 整数 2–20，必须小于 coef_bits |
| InvSqrt | coef_bits | 17 | 整数 3–30 |
| InvSqrt | square_bits | 28 | 整数 3–40 |
| InvSqrt | product_bits | 28 | 整数 3–40 |
| InvSqrt | result_bits | 29 | 整数 3–40 |
| DFTHC-SOS | brot | 12 | 整数 1–30 |
| DFTHC-SOS | source_brot | 12 | 整数 1–30；与来源角度字编码一致 |
| DFTHC-SOS | batch_size | 8 | 整数 1–75；组合后还须满足 qubit 限制 |
| DFTHC-SOS | prefix_bits | 0 | 整数 0–num_bits；num_bits 来自所选数据集 |

默认值是当前参考生成器默认，不是当前最佳。界面另提供“加载参考默认”和“复制当前最佳”；例如本日 InvSqrt 最佳为 12/17/28/27/28，必须从其记录动态读取。

化学参数不能只逐项判断合法。后端还要计算所选构造的工作位占用并验证实际每个 ANGLE 电路不超过 128 qubits。source NPZ/upstream 来源使用注册 ID 与哈希选择，不能接收任意服务器绝对路径。

模型设置：

- 新增项目专用、按模式可选择的 model/reasoning/service_tier；不通过网页编辑全局 `~/.codex/config.toml`。
- 初始值导入当前解析结果；本日观察值为 `gpt-6-astra / ultra / default`，不是永久写死的推荐。
- 可用模型及强度以安装的 CLI/账户支持信息为准；支持信息不能确认时明确提示，不自动替换为另一个模型。
- 启动时显式传入选定配置，记录请求值和有效值；不记录认证信息。
- 原生项目配置也支持覆盖全局设置，具体优先级参考 [OpenAI 官方配置说明](https://learn.chatgpt.com/docs/developer-settings)。Web 首版应统一自己的项目配置来源，避免两套设置相互遮盖。

资源设置默认延续现有 CPU20、180 GiB、RSS 提前停止170 GiB、GPU0/1、磁盘余量20 GiB。页面可在授权上限内下调。存储根、解释器、Conda 环境和认证属于迁移/运维设置，不作为运行中的普通滑块。

## 5. 队列、预算与控制语义

### 5.1 作业分类

| kind | 调用 Codex | 典型行为 |
|---|---|---|
| local_experiment | 否 | 创建候选、初筛、生成；按请求选择完整验证 |
| local_validate | 否 | 官方完整验证，或适用的 DQI 独立复核 |
| local_promote / prepare_preview | 否 | 执行现有门槛，更新最佳或准备预览包 |
| optimize | 是 | 研究、改代码、实验、验证、记录 |
| smoke | 是 | 现有 Codex/MCP 只读连通检查 |
| submit | 是 | 通过现有 Kaggle MCP 上传和提交 |
| reconcile | 是 | 通过现有 Kaggle MCP 查询与登记 |

查看页面、筛选/比较、读取报告、查看本地状态和普通刷新不调用模型。submit/reconcile 当前需要模型；若未来新增直接 MCP 客户端，应另行验证认证与等价性，不能提前宣传为零模型消耗。

### 5.2 队列与窗口

1. 可执行的用户计算任务按持久 FIFO 执行，同一时刻一个受监督计算作业；blocked 保留相对顺序但不占执行权，不能让预算不足的模型任务挡住本地实验。
2. 自动 slot 到期只创建一次意图，沿用已有去重规则；队列持久化不能将过期 slot 无限补跑。
3. 有效窗口内的提交/对账在空闲时优先；不抢占已运行任务。普通自动优化不能持续插队阻塞用户作业。
4. 默认保护区间为 19:25–21:15，覆盖准时提交与对账。当前 runner 允许对账在20:55后的两小时内启动；若21:15仍有当日可执行的对账未完成，延长保护至对账结束，或最晚开工窗口22:55过期。已在窗口内启动的对账最多继续20分钟并完成清理，因此迟到时可能保护至23:15及清理结束。已结束、无需对账或明确过期后解除保护，不无限等待。后端根据当前配置和任务状态计算并展示结束条件。
5. 普通手动作业启动前检查请求的最长时长和清理余量；不能在保护区间前结束则继续排队。用户可明确缩短预算后创建替代作业，系统不静默修改既定请求。
6. 自动优化按自身窗口设置最长截止；新作业也不能越过比赛截止。无时间空间可执行时返回明确原因。
7. 排队位置是顺序，不是准确开工时间；任务运行时间不可知时不编造 ETA。
8. 浏览器断开、刷新或 Web 服务重启不取消已接收作业。
9. 首版不让手动和自动计算并行。底层 Codex 子代理仍属于同一个受监督顶层任务，共用资源范围。

### 5.3 每日模型次数

计数单位定义为“顶层 Codex 任务启动尝试”，不是消息数、模型 API 请求数或 token：

- optimize、smoke、submit、reconcile 计入；纯本地作业不计。
- 子代理用量属于所在顶层任务，但一次数可能包含多次模型请求；页面说明次数限制不是费用或 token 硬上限。
- 建议初始总上限 6 次/北京时间日，与当前四个优化窗口及提交/对账相符。其中预留提交 1 次、对账 1 次，研究/诊断/手动模型任务共用其余 4 次。此为开发默认，不在本文编写时更改运行系统。
- 当天不存在合格改进时，新增的确定性提交预检应在启动 Codex 前跳过，避免为单纯“无改进”消耗模型任务。需要平台读取才能判断的情况依然说明调用成本。
- 保留次数属于总上限，不能在总次数用尽后暗中额外启动。用户下调总上限时必须同时配置可满足的预留值。
- 排队不占次数。启动前在同一短事务内重新检查并预留，防止手动/自动竞争。
- `budget_date` 固定为持久启动预留的北京时间日期，同时记录实际 `started_at`。如果确认尚未 spawn 且已经跨日，撤销旧预留并按新日重新检查/预留；已经启动或无法确认时不迁移、不释放原预留。文件写入与进程启动不能保证原子跨午夜，界面分别展示预算归属日和实际启动时间。
- 只有能证明子进程尚未启动的本地错误可释放预留。开始后的失败、取消、超时、断网或结果未知仍占一次；重试是新尝试。
- 重启、修改上限、清空浏览器不会清零。导入现有运行记录时按已知顶层启动证据去重，缺失覆盖明确说明。
- 达到今日上限时允许标为等待预算的队列项，必须显示不会立即启动；不能假装已进入运行。纯本地作业仍可排队和执行。
- 不新增购买额度、API key 付费回退或自动升级模型。

### 5.4 取消与中断

~~~mermaid
stateDiagram-v2
  [*] --> queued
  queued --> blocked
  blocked --> queued
  queued --> starting
  queued --> cancelled
  blocked --> cancelled
  starting --> running
  starting --> cancel_requested
  starting --> failed
  starting --> unknown
  running --> completed
  running --> failed
  running --> cancel_requested
  cancel_requested --> cancelled
  cancel_requested --> completed
  cancel_requested --> failed
  cancel_requested --> unknown
  running --> timed_out
  running --> resource_stopped
  running --> unknown
~~~

上述为作业执行状态，不是科学验证结论。blocked 要附预算/窗口/资源/配置等原因；unknown 要经过进程与结果对账才能转为确定状态。

“取消排队”携带预期状态和 revision，仅在 queued/blocked 时生效。若请求抵达时已进入 starting/running，返回409和当前 run ID，不能自动升级为停止。starting 阶段也必须通过单独确认的停止操作；可证实未 spawn 时直接完成取消并释放模型预留，否则由监督器确认进程结果。停止请求与自然完成竞争时保留真实完成状态和停止请求记录，不能将已成功完成的作业改写为 cancelled。

运行停止经过 supervisor，按 run ID、PID 和进程启动身份定位，先 TERM，再在限定清理期限后 KILL 仍存活的该任务后代。HTTP 端不接受 PID，不运行 `pkill codex`。取消请求先持久化，再发信号；返回 accepted 不等于已经停止，直到确认进程结束才显示 cancelled。

上传已经预留或发出时，取消仍需保留外部不确定状态。未写完的验证不能生成 PASS；已完成且绑定有效的此前结果保留。

### 5.5 配置版本

配置采用 draft → validated → active revision。保存前展示差异；回滚复制旧内容形成新 revision。

- 新创建作业冻结配置快照；修改默认不暗改已排队/已运行作业。
- 若想修改已排队任务，取消后复制为新作业，保留来源关系。
- dispatch 仍检查最新资源/预算政策和截止；若旧快照超过新上限则 blocked，而不是继续按旧授权启动。
- 当前运行继续使用自己的预算，界面显示“仍使用 vN”；若要立即停止，应单独操作。
- 调度器配置不能只改 JSON 就宣称全部生效。需要版本确认/重载回执；需要重启的字段展示明确状态。
- 存储根/锁目录/环境变化只能在停机迁移流程中应用，防止不同进程使用不同运行锁。
- 前端保存携带预期 revision；冲突返回 409，展示新差异后重试。

## 6. 数据定义与状态可信度

### 6.1 四个相互独立的状态维度

| 维度 | 示例 | 依据 |
|---|---|---|
| 执行 | 排队、运行、正常退出、取消、超时、状态待核实 | 作业、进程身份和结束记录 |
| 科学证据 | 未验证、初筛拒绝、官方 PASS/FAIL、额外诊断结果 | 候选绑定的验证报告 |
| 选择 | 当前最佳、未改进、证据不足、待晋级 | pipeline 门槛及晋级事件 |
| 平台 | 未提交、已预留、已接收但评分未知、已评分、拒绝 | 脱敏平台回执及查询记录 |

`result.status=completed` 只说明该 agent 运行正常结束。可能没有产生候选或没有改进。生成报告的 `official_validation=not_run` 是当时快照，不能覆盖后来 candidate 绑定的 PASS。

### 6.2 本地指标定义

- 单题成本降幅：`1 - candidate_cost / reference_cost`。
- 相对组合改善：`((ref_dqi/new_dqi) * (ref_invsqrt/new_invsqrt) * (ref_dfthcsos/new_dfthcsos)) ** (1/3)`。
- 比较基准必须是明确的候选组合；“原始样例”“本项目初始提交”“上次已提交”分别命名，不能混用。
- 官方参考成本齐备且契约相同才计算本地估计的官方综合分，仍需标明非平台返回分数。
- 本地报告 `score` 映射为 `official_cost`，方向是越低越好。
- DQI 显示 num_qubits、toffoli_count、effective_error_rate、empirical_error_rate、repetition_factor、错误数和 shots；误差上界与实测比例分开。
- InvSqrt 显示 num_qubits、toffoli_count、t_count、toffoli_equivalent、worst_error_over_tolerance、worst_x 和 shots。
- DFTHC-SOS 显示整个 block encoding 的资源、lambda_eff、残差指标；ANGLE 单电路宽度单列，不能当作整个任务的 Q。
- 不同验证器/任务契约的结果标为不可直接比较。运行环境改变须区分历史测量仍可阅读与当前提交证据需要复核。
- 导入基线标注 `imported_official` 与历史验证器指纹缺失，不能显示为当前运行重新完成验证。

### 6.4 读模型与一致性

- 页面读取原子 JSON 快照，不在请求线程中调用长时间占锁的 pipeline status。
- 所有 API 快照返回 observed_at、source_updated_at（可为空）、revision、freshness、consistency。
- 文件尚未出现、写入中、解析失败、路径不合法分别处理；保留最后一次有效快照并标记 stale/partial。
- JSONL 只消费完整行；以字节偏移和事件 ID 增量读取，不重复扫描整个日志。
- 单文件已更新但关联报告未可见时标 partial；不能立即给出成功或篡改结论。
- 哈希全量检查应是受控维护作业或基于稳定指纹的缓存结果，不能每次刷新读取 GB 级电路。
- 旧心跳和进程状态分别展示；使用 PID 起始身份避免 PID 复用误判。新增心跳采集不依赖长任务返回。
- 历史模型/usage/阶段数据缺失为 null/未记录，不填 0，也不推断为当前默认。

### 6.5 实时资源与 token

建议每 2 秒采样当前任务资源，每 5 秒刷新一般状态；事件采用流式推送。采样进程应轻量，只关注受监督的进程树，不采集整机无关进程的命令或环境。

CPU 按差分计算核数；RSS 保留已有求和口径，并说明共享页可能重复计入。GPU 若只能读取设备总利用率，必须标为设备级、可能含其他进程；不能归因给当前作业。无法获取数据时保留 unknown。

usage 保留原始输入、缓存输入、输出、推理字段及其来源。缓存通常是输入的细分，不能盲目叠加；显示覆盖范围，不提供未经验证的总费用或余额转换。正在运行、异常终止或子代理统计缺失时，合计标为不完整。

## 7. 后端架构与持久化

推荐采用 Python FastAPI 后端、React + TypeScript 前端，构建后由同一个本机服务提供静态文件与 API。沿用现有 Python 项目有助于复用校验逻辑；组件化前端用于复杂表单、比较和队列状态。依赖版本在实施时验证与 Python 3.13 的兼容性并锁定，本文不声明已安装。[FastAPI 文档](https://fastapi.tiangolo.com/) · [React 文档](https://react.dev/learn)

事件通道使用 SSE：服务端推送状态，用户操作通过普通 HTTP。浏览器 EventSource 支持事件 ID/重连机制，具体实现仍需服务端保留游标与重放窗口。[MDN SSE 文档](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

控制事务要求：

- 使用独立短时 control.lock；不能复用长期持有的 pipeline.lock 做 HTTP 请求锁。
- 同一次 dispatch 的“允许启动、次数预留、启动意图”在同一原子控制状态更新中提交。
- 记录执行身份后才进入 running；不能先返回 running 再尝试创建进程。
- 操作日志与状态跨文件时采用可重放的持久意图/待发布事件机制；恢复后以 operation_id 去重。
- spawn 与落盘之间崩溃时，以 supervisor/run 身份核实，不盲目重新 spawn；不能确认则 unknown 并保留次数。
- 原 pipeline 台账继续作为最佳候选及提交门槛的唯一业务真相；UI 控制状态不手写 PASS、最佳或平台分数。
- 稳定写入使用临时文件、fsync、原子替换，并在目标 GPFS 上验证锁与恢复行为。
- 大文件流式读取/下载；列表索引仅保存小型元数据，可从原始证据重建。

| GET /jobs?state=&cursor=&limit= | 队列/历史及分页游标 |
| GET /jobs/{id} | 作业快照、等待原因、关联运行与实验 |
| GET /runs/{id} | 阶段、有效配置、资源/usage覆盖、报告入口 |
| GET /events?run_id=&after= | SSE 增量事件；支持 Last-Event-ID |
| GET /experiments?task=&validation=&cursor= | 实验摘要；排序与分页 |
| GET /experiments/{id} | 参数、谱系、证据、资源与可执行动作 |
| GET /experiments/compare?ids= | 同题 2–4 个候选的标准化比较 |
| GET /research | 假设、来源与复现覆盖 |
| GET /submissions | 每日台账、平台结果和未知状态 |
| GET /config | 当前默认版本、待生效状态、运行采用的版本 |
| GET /parameter-schemas?generator_revision= | 算法字段、联合约束、模型支持信息 |
| GET /usage?date= | 次数账本、已观测token及统计覆盖说明 |
| GET /artifacts/{registered_id} | 白名单小报告/显式下载对象 |

默认列表每页 50 条，最大 200。请求取消不等于作业取消。SSE 使用单页面共享连接；重连去重，游标超出保留区间时返回 resync 事件并重拉快照。

### 8.2 写操作

| 方法/路径 | 行为 |
|---|---|
| POST /jobs/preview | 无副作用预检：参数、预算、配置、窗口及预计排队原因 |
| POST /jobs | 持久接收作业，返回 202 与 job_id |
| POST /jobs/{id}/cancel-queued | 附 expected_state/revision；仅取消 queued/blocked，已启动返回409 |
| POST /jobs/{id}/stop | 单独确认后附 run_id/revision；请求停止指定 starting/running 作业，返回受理状态 |
| POST /scheduler/pause | 暂停后续自动任务 |
| POST /scheduler/resume | 恢复未来自动任务，不补跑过期 slot |
| POST /scheduler/stop | 原子禁止新 dispatch 后停空闲调度器；存在活跃或未知作业返回409 |
| POST /scheduler/start | 启动唯一项目调度实例 |
| POST /config/preview | 校验配置差异和生效范围，无副作用 |
| POST /config/revisions | 保存新配置版本，附预期 revision |
| POST /config/activate | 请求应用指定版本，返回 applied/pending_restart 等 |
| POST /research/{id}/update | 更新假设排序/状态/备注；保留变更记录 |

validate、promote、submit、reconcile 都通过 POST /jobs 的受控 kind 发起，不建立绕过调度的执行 API。提交中心的“查询平台”如需 Codex，点击前明确次数消耗；后台刷新只读现有台账。

会话入口另设 `POST /session`（以引导密钥建立会话）、`GET /session`（读取当前会话/CSRF信息）、`DELETE /session`（退出）。认证请求体不写日志；会话入口不创建业务作业，业务幂等规则适用于上表操作。

写请求使用 `Idempotency-Key` 和请求体指纹：

- 同 key、同正文返回同一 operation/job；并发双击只能创建一个。
- 同 key、不同正文返回 409。
- 网络超时后，客户端先用操作 ID 或相同 key 查询/重试，不换 key 再创建。
- 配置/候选状态需要 revision 预期值，冲突不得悄悄覆盖。
- 表单提交后先显示“已入队”，只有 supervisor 确认才显示运行。
- 不确定远端提交不能由通用重试按钮再次发送。

标准响应示例：

~~~json
{
  "operation_id": "op_example",
  "job_id": "job_example",
  "status": "queued",
  "observed_at": "2026-10-29T10:00:00Z",
  "revision": 18,
  "blocked_reason": null
}
~~~

错误结构：code、message、field_errors、retryable、operation_id、current_revision。至少区分 INVALID_PARAMETERS、CONFIG_CONFLICT、STATE_CONFLICT、DAILY_MODEL_BUDGET_EXHAUSTED、PROTECTED_WINDOW、EVIDENCE_STALE、ALREADY_ATTEMPTED_TODAY、SUBMISSION_NEEDS_RECONCILIATION、INSUFFICIENT_DISK、CAPABILITY_UNAVAILABLE。错误不得包含凭证或原始命令环境。

## 9. 私有部署与数据保护

默认只监听服务器 `127.0.0.1:8765`，端口可配置。访问示例：

~~~bash
ssh -N -L 8765:127.0.0.1:8765 USER@SERVER
~~~

然后浏览器访问本机 `http://127.0.0.1:8765`。此命令仅是部署示例，本次未运行。

访问控制与渲染要求：

- SSH 身份提供宿主访问边界；Web 仍限制 Host/Origin、使用会话与 CSRF 防护，避免本机浏览器跨站触发写操作。
- 首次会话引导密钥只存服务器私有文件，用户经 SSH 读取并在本地登录页通过 POST 建立会话；不写入共享日志、URL 查询串或版本库。除登录入口外，全部数据 API、SSE 和产物下载均验证会话。会话 cookie 使用 HttpOnly 和适当 SameSite；HTTPS 部署时启用 Secure。
- 无第三方 CDN 脚本、遥测或将实验信息上传外站的前端组件；静态资产本地提供。
- 文件按注册 ID 解析，realpath 必须在允许根目录内；检查符号链接、路径穿越、文件类型和大小。
- 不提供任意目录浏览，不暴露 transport-env、Codex/Kaggle 凭证、环境变量、签名 URL 或未审查的原始日志。
- Markdown、研究标题、模型文本、来源描述均按不可信文本渲染；禁用原始 HTML，外链限制协议。
- supervisor 的控制通道只接受结构化白名单动作；前端表单不能构成任意 shell。
- 首版无公网监听和多账户权限。以后若开放内网/公网，另行设计认证、TLS、权限和审计。

只读服务与计算使用同一服务器时，监控也计入整体资源规划。为 Web/采样器保留少量 CPU/RAM，dispatcher 给计算子进程的预算不得再额外叠加到用户上限之外；不能把20核、180GiB理解成每个组件各一份。

## 10. 运行、恢复与迁移

- 前端构建和后端依赖在实施阶段安装；Python 遵守现有 Conda 选择及绝对解释器规则。先检查已有环境，不能默默创建/修改 base。
- Web 和调度器独立管理。恢复 Web 不重复启动作业；恢复调度器先对账遗留 running/starting/预留记录。
- 活跃任务需有 PID 起始身份、run ID 和 supervisor 身份；不能只凭 PID 或旧 heartbeat 认领。
- 模型预算和提交额度状态随数据盘迁移；浏览器状态可以丢弃，服务端台账不能清空。
- 数据根或解释器迁移必须停止相关执行实例并验证新旧锁域一致；只保留一个执行宿主。
- 未完成上传在迁移前优先对账，无法确认时保留阻塞状态。不能用迁移清除每日名额。
- 历史文件采用只读适配，不批量改写所有候选。新字段缺失用 unknown 和来源限制表达。
- 升级失败可回退 Web/控制层版本；保留原 CLI 操作入口和实验原始文件。回退前确认没有新格式状态被旧代码误读。
- 本容器无系统 init；部署文档应明确重启后的启动方法。网页“服务正常”必须来自当前进程证据。

## 11. 验收标准

### 11.1 人能够完成的操作

| 编号 | 场景 | 验收 |

| UX01 | 打开首页 | 能判断当前任务、平台评分是否未知、下一提交窗口、是否暂停 |

| UX05 | 本地实验 | 浏览、预检和执行均不暗中调用 Codex |

### 11.2 功能与故障用例

1. 两个并发请求使用同幂等键，只产生一个作业；正文不同返回409。
2. 手动与自动同时争抢最后一次模型预算，仅一个获得预留。
3. 排队取消不计次数；启动后失败/超时/取消占次数；跨午夜和重启不重置。
4. 总上限及提交/对账预留共同生效，任何阶段不能绕过总上限。
5. 下调资源上限后，超限的已排队快照 blocked；当前任务显示旧快照。
6. 长手动作业不能挡住提交保护窗口；不会被系统无提示强行抢占。
7. 启动意图落盘后崩溃，重启不会重复 spawn；无法认领的状态标unknown。
8. 停止按 run ID 与 PID 起始身份定位，PID复用不能误杀其他任务。
9. 完整验证中途终止不生成PASS；已有有效历史证据不会被抹除。
10. pipeline 验证长期占锁时，总览仍能读取最近有效快照，并显示其时间。
11. JSONL 半行、文件原子替换、短暂缺失、跨文件不同步均不导致假成功。
12. SSE 重放去重；游标过期后重拉快照；页面断线不显示任务已停止。
13. 提交 reserve 后断网只允许对账，不重新上传；缺字段不覆盖已确认评分。
14. 提交预览过时，dispatch 重新选择最佳组合；不上传早先旧预览。
15. 平台拒绝与本地PASS并存时，两者都显示并保留原因。
16. 修改已验证产物或验证器后，晋级/提交受原门槛阻止，UI展示证据失效。
17. 生成报告 still not_run、候选已有正式PASS时，最终验证状态来自候选证据。
18. completed 的研究运行未产生候选时，显示运行结束/无改进，不能显示实验验证通过。
19. 假设收益先验不能混入实测趋势；跨题原始成本不能同轴排名。
20. 路径穿越、向外符号链接、任意PID、恶意Markdown、跨站写请求均被拒绝或安全渲染。
21. 浏览/筛选/普通轮询不启动Codex；触发对账的模型消耗在操作前可见。
22. Web 重启不影响受监督作业，重复启动不会产生第二个调度执行实例。
23. 取消排队请求与启动竞争时返回状态冲突，不能暗中停止任务；停止与自然完成竞争时保留真实结果。
24. 昨日有ID但无评分的提交不占今日名额；昨日无ID的不确定上传仍阻止新上传。
25. 启动预留后跨午夜，已启动/未知情况不迁移预算；确证未启动才按新日重新检查。
26. 迟到对账动态延长保护区间并优先执行；过期后结束等待，不挤占下一日窗口。
27. 模型预算不足的队首不阻塞本地任务；暂停自动调度后手动作业仍遵守统一门槛执行。
28. 调度器有活跃/未知任务时停止请求返回409；停止过程与新 dispatch 互斥。
29. 未登录访问数据API、SSE和下载被拒绝；登录/退出有效，认证请求体不出现在日志中。

### 11.3 验证层次与性能目标

- 后端单元测试：状态归并、参数联合约束、预算日期、配置revision、幂等、路径与输出过滤。
- 集成测试：临时数据目录、假模型进程和假MCP回执，覆盖启动/停止/崩溃/未知状态；测试不上传真实比赛文件。
- 浏览器端到端：上述核心人工操作、断线重连、双击、配置冲突、可访问性和窄屏查看。
- 首个部署验收只读连接真实状态；受控计算操作用明确的新候选。复用既有科学验证，不为页面开发重复跑全部科学测试。
- 目标负载定义为1万条实验元数据、1000次运行摘要：常用已缓存查询P95小于1秒，健康网络事件延迟目标小于3秒。冷索引显示加载状态，不阻塞所有页面。
- 任何这些性能数字都是开发验收目标，尚未测量。GB级产物不进入常规列表响应，长历史需分页/降采样。
- 普通界面刷新不得读取敏感文件、调用模型或全量校验大型电路。
- 状态有文字和图标，不仅依赖颜色；按钮可键盘操作，危险动作有明确目标和结果说明。
